2. **Entities + repositories** mapped to V10 (`@Version` where the table has `version`; `ddl-auto=validate` must pass): Category (2 levels, parent), Brand, Product, Sku, PriceHistory.

4. **Seed**: `catalog/seed/CatalogueSeedLoader` (`ApplicationRunner`, enabled by `dna.seed.catalogue.enabled`; extra property `dna.seed.catalogue.publish` (env `DNA_SEED_CATALOGUE_PUBLISH`, default false) publishes the seeded products): reads `classpath:seed/catalogue-2026.csv` (strict RFC 4180, UTF-8, header `product_key,product_name,brand,category_l1,category_l2,code,sku_name,unit_name,conversion,is_base,price,price_visible,needs_confirmation,spec`; empty `category_l2`/`spec` = null; NEVER normalise `code`), one transaction, creates missing categories/brands by name, one product per `product_key` through `saveAggregate(..., SEED)` (`spec` -> `spec_line`), idempotent (skips SKUs whose `code_key` exists; second run writes nothing), logs a one-line summary. The CSV (69 rows, 32 products, sum of prices 23.600.440) is already in your worktree. Tests: `CatalogueSeedCsvTest` (69 rows, 32 keys, one base per product, conversions positive, the 2 flagged rows are `SV465-4L- T80` and `SV465-4L- G8` with price_visible=false/needs_confirmation=true, `SV300-3L-Gói` 3229 and `SP000014` 32290 visible and unflagged, price sum 23600440) and, if Docker/Testcontainers works, a `CatalogueSeedLoaderIT` (empty DB -> 32 products / 69 SKUs, second run no new rows).

- Every read endpoint is cheap (no N+1 explosion: fetch SKUs per product page in one query; the catalogue is ~32 products, in-memory filtering is fine).
- Build/test: `mvn -B -f <your worktree>\apps\api\pom.xml test` (Docker Desktop is running; ITs use Testcontainers `postgres:18`, random ports only).
